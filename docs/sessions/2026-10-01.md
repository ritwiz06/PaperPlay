## Problems and how they were solved

- **A write to `status.md` was refused** because the file had changed since it was last read.
  It was re-read, then rewritten.
- **The first `check:docs` run found 23 problems,** all expected. Each was cleared by
  writing the missing document or section.
- **The status page called `843050f` a commit that "passed `check:gate`".** G1 failed on it,
  so it now says that every gate script passes there.
- **The hook-seed check takes 6.4 s in Vitest.** That is 20 seeds × 1,200 steps, measured
  every step; a step takes 77 µs and a measurement 46 µs. It was kept, with an explicit
  timeout, because it is what catches the pinned seed drifting.
- **Google serves variable fonts to current browsers,** one file covering every weight. A
  request naming a browser without variable-font support returned one static file per
  weight.
- **Vite inlined the two 2.6 KB Fredoka latin-ext files into the CSS,** so every visitor
  would have downloaded them. `assetsInlineLimit` now leaves woff2 files alone.
- **Fredoka has no tabular figures,** so readouts and values sit in fixed-width,
  right-aligned slots.
- **React's compiler lint rules** forbid ref access during render and synchronous setState
  inside effects.
  - The stage keeps its mutable view in a ref, touched only in effects and handlers.
  - The WebGL fallback is flagged with a DOM attribute instead of React state.
- **Pointer capture on the whole stage would have swallowed clicks on its tool buttons.**
  The pointer handlers moved to the canvas host.
- **`getByRole("button", { name: "Play" })` also matched "Replay same seed"** (substring
  matching). The tests now use exact names.
- **TypeScript 6 checks side-effect CSS imports,** so the web test project needed Vite's
  client types. The UI test project reached the React folder without JSX settings, so it
  now leaves that folder to its own tsconfig.
- **The first screenshots showed three problems:**
  - the legend wrapping to two lines;
  - dark arcs at the stage's top corners, from the frame's background;
  - the field cropped on the phone layout.

  The fixes were shorter legend meanings, a transparent frame with a dark hint bar, and a
  new fit rule with relative fog. The old rule had cropped a field corner even at 1.2:1,
  and its cap of 2× came from the fog, which would otherwise have hidden the field. The new
  test checks that every field corner and post top fits at six stage shapes, from 16:9 to
  a phone held upright.
- **Deleting `apps/web/src/stage/local-stage.ts` left two concept entries pointing at it.**
  `check:docs` failed inside the gate, as it should. The two paths were updated in the
  same commit, so every commit stays consistent.

Acceptance conditions, in plain language:
- **Land:** `main` moves only to a commit whose gate passed locally and whose CI run, on that
  exact commit, is green. Land refuses:
  - a dirty tree, main itself, or a spike branch;
  - a branch behind `main`;
  - a failing gate, read from its own exit status;
  - red CI.

  The hook refuses any push that would move `main` to a commit land has not recorded.

## Concepts introduced

## Decisions made and needed

**Made by the owner:**
- `main` moves only through `npm run land`, guarded by a pre-push hook (ADR-0009, amended).
- PaperPlay builds for AI/ML, biomedical and scientific papers, with the flocking world as
  the reference example (ADR-0021). The brief and the roadmap say so. G3 and G4 are re-planned
  in `docs/design/every-paper.md`, for the owner's review.

**Made by me, for the owner to confirm (ADR-0009's amendment):**
- **Land refuses any branch not named `<gate>/<topic>`,** so a spike cannot be landed by
  mistake.
- **The land record lives in `.git/paperplay/landed/`,** outside the tree.
- **npm's `prepare` script installs the hook** on every install; land installs it too, if
  it is missing.
- **Origin's `main` moves first.** Once it has, a failure while tidying up locally is a
  warning, not a refusal.
- **Land gates the commit it moves `main` to.** The commits inside a slice are not gated one by
  one.

**Made by me, for slice 2 (for the owner to confirm):**
- **Predictions (ADR-0023):** each level's two choices are the stated outcome and its opposite; the
  bonus level's explanation is a teaching choice; `runrecord/3` keeps predictions as notes, not
  events; the contract still allows a level without one.
- **The stated effects now say "this world" and "the other world".** "The left flock" was wrong
  on a phone, where the worlds stack, and its "right" tripped the test for scoring words.
- **Context loss (ADR-0022):** the notice's words; a reload builds a new renderer for the same
  scene, never reloading the page; focus goes back to the stage.
- **The chart's sizes:** 140 px tall, or 120 px below 480 px wide, with 12 px labels.
- **The speed button's word, "Speed", is hidden on a phone,** like the HUD's other labels.
- **Level 5's counter shows the birds inside rocks right now** (E20), not a running total. Its
  rocks, and the rocks on the stage, come from a new read-only query, Q4.
- **Rock markers cast no shadow,** like the valley's own rocks. That is the fix for the
  fork's stall, and it changes how level 5 looks a little.

**Needed from the owner:** whether to pay for GitHub's branch protection, which would refuse
the same pushes on the server (ADR-0009's amendment).

## Problems and how they were solved

- **The test for scoring words found two false alarms, and one real fault behind them.**
  - **"The right flock bunches far tighter"** used "right" as a direction. On a phone the two
    worlds stack, so "left" and "right" were wrong there anyway. The effects now say "this
    world" and "the other world", and the sweep's record follows, byte for byte.
  - **Level 5's question, "what would a model … get wrong"**, now asks what it would "fail to
    show".
- **A HUD test assumed the guide survives the fork.** The fork covers the HUD, so the guide
  starts afresh when it closes. The test now acts again first.
- **Land refused level 5's first landing, as it should.**
  - The gate passed locally on `c6a57bf`, but CI's run 38022778778 failed. `rocks.spec.ts`'s
    fork test ran past Playwright's default 30 s: it took 16 s locally, and CI's runner is
    slower (the browser tests took 550 s there).
  - Land read the failure, kept `main` at `45afde3` and said why:

    ```
    land refused: CI's run https://github.com/ritwiz06/PaperPlay/actions/runs/38022778778 on c6a57bf did not succeed (completed, failure); main was not moved
    ```

  - `f849035` sets 90 s, as the other long fork tests do. On the same run, the What-if test
    in `levels.spec.ts` took 24.8 s against its 30 s, so the predictions branch gives it 90 s
    too.
- **My first two theories for level 5's stall were wrong.** I thought the rock needed a
  shader of its own, then that sharing the birds' shader would avoid it. Timing each variant
  found the cause: the rock's shadow draw, whatever its shader.
- **Land first treated a failed local tidy-up as a refusal,** even after origin's `main` had
  moved. Found by reading the code before landing. Now it reports the land with a warning, and
  a test covers it.

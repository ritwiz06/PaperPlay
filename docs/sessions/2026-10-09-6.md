Acceptance conditions, in plain language:
- **Land:** `main` moves only to a commit whose gate passed locally and whose CI run, on that
  exact commit, is green. Land refuses:
  - a dirty tree, main itself, or a spike branch;
  - a branch behind `main`;
  - a failing gate, read from its own exit status;
  - red CI.

  The hook refuses any push that would move `main` to a commit land has not recorded.

## Decisions made and needed

**Made by the owner:**
- `main` moves only through `npm run land`, guarded by a pre-push hook (ADR-0009, amended).
- PaperPlay builds for AI/ML, biomedical and scientific papers, with the flocking world as
  the reference example (ADR-0021). The brief and the roadmap say so. G3 and G4 are re-planned
  in `docs/design/every-paper.md`, for the owner's review.

**Made by me, for the owner to confirm (ADR-0009's amendment):**
- **Land refuses any branch not named `<gate>/<topic>`,** so a spike cannot be landed by
  mistake.
- **The land record lives in `.git/paperplay/landed/`,** outside the tree.
- **npm's `prepare` script installs the hook** on every install; land installs it too, if
  it is missing.
- **Origin's `main` moves first.** Once it has, a failure while tidying up locally is a
  warning, not a refusal.
- **Land gates the commit it moves `main` to.** The commits inside a slice are not gated one by
  one.

**Needed from the owner:** whether to pay for GitHub's branch protection, which would refuse
the same pushes on the server (ADR-0009's amendment).

## Problems and how they were solved

- **Land first treated a failed local tidy-up as a refusal,** even after origin's `main` had
  moved. Found by reading the code before landing. Now it reports the land with a warning, and
  a test covers it.

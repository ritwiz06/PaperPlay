# Session 2026-10-29: PaperPlay on one endpoint

## Goal

The owner: "why 2 different end points needed, put them under 1 only". PaperPlay ran as two servers
on two ports, the web app and its API; now one command, one process, one port, the API at `/api`.

## What I read

ADR-0059, the web app's Vite config, the API's entry and server, `pipeline:live serve`, and the
specs that call `/api`.

## What changed, by commit

`g3/one-endpoint`: the API inside the web app's development server (`apps/api/src/dev.ts`, the Vite
config's `paperplay-api` plugin); `pipeline:live serve` starts that server with live calls; the
README and the tests. Then the docs.

## Checks run, exact output

- `npm run dev` printed "PaperPlay: http://127.0.0.1:5180/create, its API at /api with recorded model
  calls"; one process listened, on 5180, none on 8787; `/api/health` answered ok, `/api/jobs` an empty
  list, and a job's events streamed through `/api/jobs/<id>/events`. The server answered 403 for the
  API's `.env` under `/@fs/`.
- `servers.test.ts` 7 of 7; the create, library, smoke and generated-world specs 22 of 22, with no
  more "ECONNREFUSED 127.0.0.1:8787" from the tests' own server.

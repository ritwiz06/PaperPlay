## Problems and how they were solved

- **Land refused `g3/families`'s first landing on its own gate.** `fork.test.ts`'s level 4 took
  6.1 s against Vitest's 5 s default, because I ran the unit suite in my worktree while land's
  gate ran its own. Nothing was pushed. The second land, with nothing else running, passed.
  The same load pushed the oracle `flock.no-alignment.stays-disordered` to 5.4 and 5.7 s in my
  own runs; alone it takes 2–3 s. I changed neither test, and run nothing beside a land's gate.
- **A capture spoiled by a save.** Vite reloads the capture page when a module it serves
  changes, so a capture or a browser run needs a tree no one edits.

- **A Mac record does not replay bit for bit on Linux, in one sample of one observable.** Land
  refused `g3/records` on red CI, before any refactor, so this is a fact about the two
  runtimes, not a regression.
  - Of 18 records, 17 replayed bit for bit on CI's Linux x86-64. In level 3's trunk, E19, the
    largest group's spread, was one ulp off at its tenth sample.
  - E19's circular mean calls `Math.cos`, `Math.sin` and `Math.atan2`. ECMAScript does not
    require them to be correctly rounded, so each engine build may round them its own way.
    Every other observable, and every step, uses only arithmetic and `Math.sqrt`, which it does
    require to be correctly rounded.
  - The test now holds the records bit for bit on darwin arm64, where they were made.
    Elsewhere, each run must be the same state for state, checked by its final state's SHA-256,
    and every observable but E19 bit for bit, with E19 within 1e-12.
  - It is the first test to compare a Mac run with a Linux run bit for bit, so architecture's
    runtime claims now say what it found.

- **The records first lived in `scripts/`, and the gate's typecheck failed:** the root
  tsconfig resolves modules the Node way, which cannot import the app's world module, since it
  imports a JSON file without an import attribute. The records belong with the app's own
  tests, whose tsconfig resolves as Vite does, so they moved to `apps/web/test/`.
